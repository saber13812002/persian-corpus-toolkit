## ۲. سازگاری Markdown با Wiki.js (نکات)

| ویژگی اسناد ما | سازگاری Wiki.js | نکته |
|---|---|---|
| Headings `#`–`##` | ✅ | — |
| جدول‌های GFM | ✅ | — |
| Code fence ```` ```text/bash/python ```` | ✅ | — |
| لینک نسبی (مثل `[](FILE.md)`) | ⚠️ **نیاز به تبدیل** | Wiki.js لینک نسبی repo را نمی‌فهمد — هنگام paste، لینک‌های نمونه‌هایی مانند `` `[INDEX.md](INDEX.md)` `` یا `` `[../PCM-20.6.4-ARCHITECTURE.md](…)` `` را یا به path wiki (مثل `/تسنیم/معماری`) تغییر دهید یا ساده‌شان کنید. **بهترین روش**: فقط بدنه را paste کنید و لینک بین‌صفحه‌ای را در wiki بسازید (Wiki.js auto-link ندارد — دستی). |
| لینک نسبی عمق‌دار `../../tasnim/web/app.py` | ⚠️ | در wiki معنی ندارد — می‌توانید حذف/ساده کنید (فقط نام فایل بماند) |
| emoji (✅ ⛔ 🚧) | ✅ | — |
| HTML خام | ❌ ندارد | اسناد ما HTML خام ندارند (فقط markdown) — امن |
| RTL/فارسی | ✅ | Wiki.js bidi را handle می‌کند؛ فقط **preview** را بعد از paste چک کنید (جدول‌های RTL گاهی نیاز به `dir="rtl"` در block settings دارند) |
| Frontmatter | ❌ استفاده نمی‌کنیم | اسناد ما frontmatter ندارند |
| Anchor/TOC | ✅ | Wiki.js TOC خودکار می‌سازد |

**قاعدهٔ paste**: هر سند را کامل paste کنید (بعضی از اسناد بلندند — API-REFERENCE ≈ 500 خط؛ Wiki.js محدودیت ندارد). بعد از paste:
1. preview را چک کنید (به‌خصوص جدول‌های 4 ستونه + code block)
2. لینک‌های نسبی شکسته را به path wiki تبدیل کنید
3. category «تسنیم» + tag (مثلاً `tasnim`، `docs`)
